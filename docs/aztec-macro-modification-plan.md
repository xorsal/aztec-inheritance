# aztec.nr Modification Plan: `compose_token` support

**Target file:** `repos/aztec-packages/noir-projects/aztec-nr/aztec/src/macros/aztec.nr`  
**Status:** Design document — implementation pending compilation of baseline AmmToken

---

## Goal

Extend `AztecConfig` with a `compose_token()` option so that:

```noir
#[aztec(AztecConfig::new().compose_token())]
pub contract Amm {
    #[storage]
    struct Storage<Context> {
        // Only pool fields — token fields injected by #[aztec]
        reserves: ...,
    }
    
    #[external("private")]
    fn add_liquidity(...) {
        self.internal._mint_to_private(to, shares); // SC-3 ✓
    }
    
    // No token functions written — generated by #[aztec]
}
```

## Step 1: Add `compose_token` to `AztecConfig`

```noir
pub struct AztecConfig {
    custom_message_handler: Option<CustomMessageHandler<()>>,
    compose_token: bool,  // NEW
}

impl AztecConfig {
    pub comptime fn new() -> Self {
        Self { 
            custom_message_handler: Option::none(),
            compose_token: false,  // NEW
        }
    }
    
    pub comptime fn custom_message_handler(...) -> Self { ... }
    
    // NEW
    pub comptime fn compose_token(_self: Self) -> Self {
        Self { 
            custom_message_handler: _self.custom_message_handler,
            compose_token: true,
        }
    }
}
```

## Step 2: Modify `aztec()` to call composition logic

```noir
#[varargs]
pub comptime fn aztec(m: Module, args: [AztecConfig]) -> Quoted {
    let config = ...;
    
    check_each_fn_macroified(m);  // validates app functions
    
    let functions = process_functions(m);
    let interface = generate_contract_interface(m);
    ...
    
    // NEW: compose token if requested
    let token_composition = if config.compose_token {
        compose_token::generate_token_composition(m)
    } else {
        quote {}
    };
    
    quote {
        $interface
        $self_call_structs
        ...
        $token_composition  // NEW
    }
}
```

## Step 3: New file `macros/compose_token.nr`

Contains `generate_token_composition(m: Module) -> Quoted` which returns ALL token
function dispatch code as a Quoted block. Since this runs INSIDE `#[aztec]`, all the
generated functions are part of the same Quoted output and get elaborated together.

The generated code includes:
1. `__aztec_nr_internals___transfer_private_to_private` + all other dispatch wrappers
2. `transfer_private_to_private_abi`, etc. (ABI structs)
3. All token `#[internal]` implementations
4. Storage validation (assert required token fields exist)

---

## Key Design Points

- `check_each_fn_macroified` runs BEFORE composition — validates only the app functions that exist in source. Token functions are generated AFTER this check, so they don't trigger the panic.
- The token dispatch code is generated inline, NOT through the registry. This avoids the timing issue where registry reads happen before injection.
- Token internal functions (`_mint_to_private`, etc.) are generated as `__aztec_nr_internals__` prefixed functions, exactly as if the user had written them with `#[internal("private")]`.
- The `self.internal._mint_to_private(...)` call from `add_liquidity` works because `CallInternal` struct has these methods generated.

---

## Blockers / Open Questions

1. **Can we generate `CallInternal` methods for composed functions?** The struct is generated by `generate_call_internal_struct(m)` which reads the internal functions registry. If token internals are generated outside the registry path, we need to either:
   - Register them manually in the registry from within `#[aztec]`
   - Extend `generate_call_internal_struct` to accept an additional list of "composed" internals
   
2. **Storage validation:** How to assert the host contract's Storage has the required token fields (name, symbol, etc.)? Options:
   - Check `m.structs()` for a Storage struct with matching fields
   - Document as a contract requirement (compile-time panic if missing)

3. **ABI and dispatch completeness:** The `generate_public_dispatch(m, ...)` reads from registries. Need to ensure composed token public functions appear in dispatch. This might require calling `external_functions_registry::add_public(m, f)` for each composed function from within `#[aztec]`.

---

## Implementation order

1. ✅ Baseline AmmToken compiles (manual, no compose_token) — validates the architecture
2. Add `compose_token` to AztecConfig (trivial)
3. Implement `generate_token_composition` with all token dispatch code
4. Wire into `aztec()` and test compilation of `Amm` with empty token section
5. Iterate on CallInternal / dispatch completeness issues
